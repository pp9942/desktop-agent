凡是「记下来、存一条、以后翻」这类需求，一律走 MCP 笔记工具，不要写进工作区文件：

- `mcp__save_note`：存笔记。参数 title 必填；content 写成"结论 + 原因 + 影响面"三段，
  不要只存一句结论——三个月后翻到的人需要知道为什么。
- `mcp__search_notes`：先搜再存。存之前先搜同名或相近标题，已存在就更新而不是新建，
  避免同一件事存出五个版本。
- `mcp__list_notes`：用户问"都有什么笔记"时用它，返回摘要列表，不要逐条打开。

判断标准：
- 会话结束后还需要的东西 → 笔记（架构决定、踩坑结论、待办）；
- 只在本次任务里有意义的中间状态 → 不要进笔记，说在回复里就够；
- 代码和配置 → 永远不进笔记，进工作区文件。

MCP 工具失败（server 没起来）时，如实告诉用户笔记服务不可用，
可以临时把内容写到工作区 `notes.md`，并提醒等恢复后迁移——不要默默丢掉。

标题规范：一句话说清「这件事是什么」，不要用"笔记1"、"备忘"这种无信息标题。
好例子：「edit 唯一性校验的设计动机」、「Windows 打包下 pytest 不可用的替代方案」。
好标题的意义在于三个月后 search_notes 能一次命中；标题含糊，笔记等于没存。

批量整理：用户要求整理笔记时，先 list_notes 拿全量摘要，
把同主题的合并（保留最早创建时间作为事实锚点），再逐条 save_note 覆盖更新；
一次会话里的合并动作不要超过十条，超过就先列方案征求用户同意。
